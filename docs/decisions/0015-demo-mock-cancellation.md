# ADR-0015: 合宿デモ用モック（demo/）の作成中止

## ステータス

2026-08-15時点の意思決定を、Issue #33（技術選定の振り返り）作成時に
後追いで記録したもの。当時は`docs/decisions/0002-demo-shortcuts.md`として
作成されていたが、本ADRが示す方針転換そのものにより同ファイルごと
削除されている（詳細は下記）。

## 決定事項

- 合宿デモ用の緊急モック（`demo/`、Expoプロジェクト`oruca-mock`として
  雛形まで作成済みだった）の作成を中止し、関連ファイル
  （`demo/README.md`・`docs/decisions/0002-demo-shortcuts.md`）を
  リポジトリから削除する
- 以後は本開発用のプロジェクト（`app/`）に直接着手する。モックデータに
  対して画面が動く状態を先に作り、バックエンド（Supabase・DDL・RLS）は
  後から接続する方針で進める（コミットb7d8fc3、2026-08-15）

## 理由（当時判明していた範囲）

- 「合宿デモ用の近道実装（demo/）が本開発の足を引っ張る」という判断。
  コミットメッセージには「作成途中で不要と判明したため」とのみ記録されて
  おり、具体的に何が不要と判断する決め手になったか（デモ自体が不要に
  なったのか、`demo/`という別プロジェクトを並行で持つコスト自体が
  見合わないと判断したのか等）の詳細は、当時のドキュメント・コミット
  履歴のいずれにも残っていない

## 振り返り（2026-10-02追記、Issue #33）

- この切り替え自体、ADRを書く前に判断・実行した点は、意思決定の
  スピード感としては悪くなかった。実際、本開発（`app/`）へ一本化した
  ことで、以後のUser Story実装はすべて同じコードベース上で進められた
- 一方で、**方針転換の理由（なぜ・いつ・何を根拠に`demo/`が不要と
  判断したか）が、ADRとして当時詳しく記録されていなかった**。本ADRは
  Issue #33の振り返り時点で判明する範囲（コミットメッセージ・CLAUDE.md
  の記述）を後追いでまとめたものであり、判断当時の具体的な根拠
  （定量的な見積もり等があったか）までは復元できていない
- **今作り直すなら変える点**：方針転換のような大きな意思決定は、
  実行と同時（またはその場）にADRとして理由を書き残しておくべきだった。
  「後で書く」と先送りにすると、本ADRのように復元できない情報が
  出てくる。この教訓自体は`docs/decisions/0005-migration-workflow.md`・
  `0014-git-worktree-parallel-development.md`の振り返りとも共通する
