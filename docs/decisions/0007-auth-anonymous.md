# ADR-0007: 認証方式（匿名ログイン、デモ用の暫定措置）

## 決定事項

- **デモ・開発初期段階の暫定として**、ユーザーのアプリ内での本人確認
  （Supabase Authとの連携）は**匿名ログイン**（`supabase.auth.signInAnonymously()`）
  を採用する
- アプリ初回起動時に自動でSupabase Authのアカウント（`auth.users`）が作られ、
  `USERS.id`はその`auth.uid()`と同じ値にする（`USERS`は`auth.users`への
  外部キーを持つ）
- メールアドレス・電話番号などの入力は不要
- アプリの再インストール・機種変更をした場合、現時点では**別人として
  扱われる**（アカウント復旧機能は今回のスコープに含めない）
- **本番では最終的にメールアドレスでの登録に移行する想定**（2026-08-18、
  開発者確認）。匿名ログインで作られたアカウント（`auth.users`）に、後から
  メールアドレスを紐付ける（Supabase Authの`linkIdentity`等）ことで、
  今の匿名ユーザーをそのまま本登録ユーザーに引き上げられる見込み。移行の
  詳細実装は別途検討する

## 理由

- US-005（OTPによる友達追加）は「友達追加時のなりすまし防止」のための
  ワンタイムパスワードであり、アプリへのログイン自体とは別の話。ログイン
  方法自体はこれまで未定義だった
- 今夜〜デモまでの短期間でRLS・バックエンド接続を進める必要があり、
  メール登録フロー（送信・確認画面・エラーハンドリング）を今から作り込む
  時間が無い。匿名ログインはSupabase Auth標準機能で追加コスト無く使え、
  RLSポリシーで`auth.uid()`を使った本人確認がすぐにできるようになる
- 本番の最終形（メールアドレス登録）は、匿名ログインのアカウントに後から
  メールを紐付ける形で移行できるため、今回の暫定実装を後で捨てずに済む

## 見送った選択肢

- **電話番号OTPログイン**：機種変更時の復旧はできるが、SMS送信コストが
  発生し、実装・検証の手間も増える
- **今すぐメールアドレス登録を本実装する**：本番の最終形ではあるが、
  デモまでの時間で送信・確認・エラーハンドリングまで作り込むのは
  リスクが高いため、匿名ログインで先にRLS・バックエンド接続を進め、
  メール登録は後続タスクとして扱う
